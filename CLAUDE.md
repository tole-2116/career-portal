## Project

Career Portal is a Bun/Turbo monorepo for a recruiting platform. The browser app is `apps/web`, the Express API is `apps/api`, and reusable types, database access, and TypeScript configuration live in `packages/`.

## Commands

Run from the repository root unless noted:

```bash
bun install
bun run dev                 # Start workspace dev tasks via Turbo
bun run build               # Build all workspaces
bun run lint                # Lint workspaces that define lint scripts
bun x tsc --noEmit          # Root TypeScript check (used by CI)
```

Web app commands (from root):

```bash
bun --filter @career-portal/web dev
bun --filter @career-portal/web lint
bun --filter @career-portal/web build
```

API development and build:

```bash
bun --filter @career-portal/api dev
bun --filter @career-portal/api build
```

Database workflows (connection settings are read by the database package):

```bash
bun run db:migrate:dev
bun run db:migrate:prod
bun run db:seed:dev
bun run db:setup:dev
bun --filter @career-portal/database db:studio
```

There is no configured test runner or test script. CI runs `bun x tsc --noEmit` and `bun run build`; it does not run lint or tests.

## Architecture

- This is a Bun workspaces monorepo orchestrated by Turbo. `apps/web` is the TanStack Start + Vite React application; `apps/api` is an Express server. Shared workspace packages are `packages/types`, `packages/database`, and `packages/typescript-config`.
- The web app's file-based routes are in `apps/web/src/routes/`; `__root.tsx` supplies the root document/layout and `router.tsx` configures the router. `src/routeTree.gen.ts` is generated by TanStack Router—edit route files, not the generated tree. Public pages and admin pages are routed separately, with shared site/admin layouts under `components/`.
- Web state/data flows through feature stores in `apps/web/src/lib/` (jobs, auth, news, inbox, taxonomy, and site/form/language configuration). These are in-memory client-side stores; `apps/web/src/data/` contains seed/mock content. Do not assume this state persists or is backed by the API/database unless the feature's implementation shows that integration.
- `apps/api` contains the server entrypoint and API implementation. Database schema, Prisma migrations, seed data, and the Prisma client export are owned by `packages/database`; domain types shared between app/API are in `packages/types`.
- The web app uses Tailwind CSS v4 and Shadcn/Radix UI components. Its `@/*` alias resolves to `apps/web/src/*`. The interface supports Vietnamese and English; localized content/configuration must preserve both language variants.
- Root CI installs with `bun install --frozen-lockfile`, then runs the root TypeScript check and monorepo build.

## Existing repository guidance

Task files under `tasks/` include a Definition of Done; when changing a task's status, move it between `backlog/`, `in-progress/`, and `done/`. Before committing task work, run typecheck and build.
